# 更换嵌入模型：重建索引并应用

已有资料后，更换嵌入模型、明确版本或向量维度，需在“设置”中完整重建后再应用。仅更换生成或重排模型，且服务器确认嵌入目标不变时，继续使用普通应用入口。

本轮页面操作已接线，后端仍在编译前整合，尚未完成构建、测试或部署。未运行自动化测试、语法检查、浏览器验收或真实模型调用。状态见[0028记录](changes/0028-model-index-rebuild/REVIEW.md)，页面由用户验收。

## 操作步骤

1. 打开“设置”，点击“读取当前配置”。核对已保存版本和已应用版本，编辑嵌入模型、明确版本与实际维度，然后“保存草稿”。保存不会替换旧配置。
2. 按需要明确测试已保存的嵌入模型及向量库连接。测试可能产生调用费用；测试成功不表示资料已经完成重建。
3. 查看“更换嵌入模型后重建索引”区域。服务器显示本次资料数量与资格；有未完任务、材料不足或权限问题时，先按提示处理，再“刷新批次状态”。
4. 点击“重建索引并应用”，核对资料数量、目标配置版本和费用说明，再确认。批次使用保存的解析材料，不重新上传、解析或转录；会调用新嵌入模型与向量服务。已有独立图片/音频向量完整核验后继续使用，不重新生成媒体向量。
5. 查看“已构建 X / Y 份”。处理中仍使用旧配置和已发布资料查询、打开来源及整理；配置保存、导入、原文件更新、删除和索引写入暂停。离开页面不取消后台批次，返回设置可重新读取进度。页面没有取消后台批次按钮。
6. 全部完成后服务器自动应用，无需再次点击普通应用。页面先确认已应用版本，再刷新能力和资料，并提示重新查询。问题和完整范围保留，整理草稿不会因批次完成主动清空。
7. 进入知识问答，明确测试当前问题与范围，核对召回片段，再按需发起问答并打开新引用。旧结果应重新查询，不能把旧来源继续当作新发布版本。

## 结果未知或失败

提交超时、断网或关闭页面后，先读取当前配置并刷新批次状态，不要立即再次创建。出现“已有模型重建批次正在处理”时等待；出现“本次模型重建未完成”时旧配置及旧资料保持可用，核对原因后按服务器资格明确新建批次。页面不自动重试。

本次范围由服务器冻结，不从当前列表分页、搜索条件或问答选择中截取。服务器要求配置管理员能编辑完整受影响资料，不会静默跳过无权限项。独立原声音、原视频索引保持自身处理流程。
