# 库内原文件预览：待后端对接契约

这是后续接口需求，不是已经实现的API，也没有向代理添加猜测的原文件路由。

## 已确认缺口

当前Java控制器只提供管理、上传/解析与索引任务，没有原文件GET接口。既存demo-image/demo-audio/demo-video属于0字节synthetic记录，不含可显示/播放的文件。前端的本地File预览不能当作这些记录的原文件，也不参与证据引用或问答。

## 后端需要提供

- 授权列表给出是否存在可读取原文件、原文件版本标识、实际MIME/size，以及当前身份是否可预览。原文件版本应与active索引版本分开：未索引文件也可能有原文件。
- 明确冻结读取路由及版本参数（本次不指定虚构可调用地址）。读取必须重新验证workspace/principal/ACL、版本与删除状态；拒绝遍历路径和任意storage URL。
- 图片/PDF/文本：正确Content-Type、长度、nosniff及no-store；不得从文档名称猜路径或信任未经校验的客户端URL。
- 音视频：支持Range、206/416、Content-Range及Accept-Ranges，或经过审查的短期可撤销同源媒体授权方式。开发header身份不能直接靠原生video.src携带，需要明确媒体传输鉴权方案；不得在URL存JWT或关闭ACL。
- 删除、撤权、版本切换时，旧读取/分段请求失败关闭。文件缺失与格式不支持应有可区别的安全错误。

## 后续前端接线

冻结API后增加独立Remote Source Adapter，再扩展前端代理的精确路由/限额/Range转发。不能为了播放大视频统一扩大现有JSON和全部响应预算。

现有PreviewResource可接收实际Blob并管理URL生命周期；本轮UI只绑定用户显式选择的本地File。库内远程读取必须额外实现身份epoch、取消请求、版本固定和权限撤销时清理；不能仅把任意远程URL塞进当前查看器。

验证必须用真实入库文件完成图片查看、音视频seek/播放、PDF/文本，以及撤权/删除/旧版本负例。完成前不得标记库内多模态预览完成。
