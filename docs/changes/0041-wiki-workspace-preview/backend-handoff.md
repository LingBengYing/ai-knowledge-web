# Wiki 工作台：后端接入候选清单

状态：仅供用户确认前端后的设计讨论，不是已批准的后端实现计划。
对应当前 `public/wiki-preview.mjs` 与 `public/wiki-preview-data.mjs`。
本轮仅参考 [nashsu/llm_wiki](https://github.com/nashsu/llm_wiki) 的信息架构，采用原创代码，未复制其 GPL 源码。

## 已有与未有的边界

- 当前预览的知识页、关系、审阅建议、来源及问答全部为明确标注的合成内容。
- 目录搜索是本地字面匹配；问答是固定案例，不是检索、重排、模型生成或线上 trace。
- 预览导入只记录文件名和大小；没有上传、解析、索引或知识编译。
- 草稿、审阅决定与设置只保存在当前浏览器；不得作为正式知识或答案证据迁移。
- 下列名称是候选领域对象和交互需求，不是新接口名称，不预先规定尚未实现的 URL。

## 1. 原始资料与可追溯来源

- 复用已有 document、revision、publication 及源文件 SHA 身份，不用预览 `id` 代替。
- 每份来源展示原文件名、当前处理/发布状态、资料版本、更新时间和原件读取资格。
- 页码、码点、视频/音频时间与帧位置必须取自服务器已有结构化 locator。
- 新前端阅读器继续执行既有来源回读与身份/SHA 校验，不相信模型生成的链接或页码。
- 资料更新、删除、重新索引后，旧回答应仍可追溯其原版本；当前可用性明确显示。

## 2. 跨文件知识页与关系

- 候选 KnowledgePage 包括稳定身份、标题、类型、版本、章节及编译/审阅状态。
- 每个章节分别关联支撑它的原始来源版本与定位；不能只有页面级文件列表。
- 一段内容可能由多份文件支撑；重复事实可以合并，来源文件身份不能丢失。
- 知识页是派生理解层；来源不足、矛盾或已失效的内容要显式标记，不能冒充原文。
- RelatedPage / Backlink 应有可解释的关联依据；图谱只是这些关系的可视化视图。
- 现有预览 `sourceIds`、`relatedIds` 只是布局数据，不能直接当生产关系表合同。

## 3. 编译、增量影响与更新审阅

- 明确区分原文件解析/索引任务与跨文件知识编译任务，分别展示状态和失败原因。
- 新增或更新来源后，识别受影响知识页/章节，生成变更建议及对应来源版本。
- 审阅页需要前后差异、影响范围、建议理由、支撑原文及当前基础版本。
- 采纳、暂不采纳、撤销必须明确实际语义与版本冲突行为，不照搬预览的本地开关。
- 删除或撤回来源时，知识页相关内容应失效、待审阅或重新编译，不能继续当有效事实。
- 先跑通一条“新增来源 → 受影响页面建议 → 人工采纳 → 新知识版本”正常链。

## 4. 查询意图与文件级结果

- 区分“哪些文件包含 X”“X 是什么”“X 如何操作/某事实是多少”，避免一律拼接片段回答。
- 找文件：以文件为结果单位，展示匹配依据与概览；有分页或截断时不声称完整列出全库。
- 解释主题：允许先展示知识页导航，再回到原始证据形成答案；未知实体不能凭常识合并。
- 操作/事实：保留适用产品、限定条件、步骤及确认信息，并给出原文或媒体定位。
- 对“灯塔”等歧义词，可区分项目与设备并让用户继续选；预览词表不能成为生产规则。
- 片段重复可合并展示，但文件去重按资料身份执行，不按正文相同删除不同文件。
- Top K 是采用片段数量，不等于匹配文件总数；文件发现与回答证据选择应分别表达。

## 5. 真实回答、过程与检索配置

- 前端只展示服务端实际回答、来源和阶段状态，不用固定示例模拟真实处理进度。
- trace 需区分未执行、召回为空、阈值淘汰、模型失败与有据回答；不得由前端猜测原因。
- 文件卡片、段落引用与 trace 应绑定同一次请求/答案及实际使用版本，防止迟到响应混入。
- 继续复用已有 OpenAI 兼容生成/嵌入协议、重排 Adapter、Milvus 与现有模型配置。
- 复用已有持久检索方式、排序、权重、Top K、阈值和配置版本，不新造一套独立配置。
- 评分解释沿用对应算法语义，相关性分数不包装成事实置信度；不预设未经验证的阈值。

## 6. 会话、草稿与用户维护

- 会话历史、上下文参与方式、删除/恢复和跨设备持久化须由后续合同明确。
- 当前预览只逐条匹配问题，不实现追问指代；不能把“预算呢”等预写案例当多轮能力。
- “存为知识草稿”需要保留答案身份与来源关系；草稿未经确认不能直接成为检索事实。
- 人工新建/编辑知识页应与模型建议、已发布版本分开，明确何时审阅与发布。
- 原始资料管理仍保留列表、筛选、目录/标签与独立详情 URL，不被图谱替代。

## 7. 多模态原件

- 文档继续读取同版本 PDF/文本；图片区分原图、OCR 与派生图注，不能相互冒充。
- 音视频继续复用真实原件及 typed 时间来源，转录、字幕、选帧 OCR 分别标注。
- 操作文档和教程可在同一答案出现；关联同产品/版本要有依据，不能按名字相近强绑。
- 预览中的时间脚本没有真实媒体，正式接入后才能验证播放、跳转和原件一致性。

## 后续验收顺序

用户先确认本轮页面与导航，再确定最小领域合同及改动范围。
首条后端主线建议用现有合成资料验证“查找文件 → 综合回答 → 同版本来源回读”。
随后接入知识页编译/审阅；每步以真实结果验收，不以预览展示或测试数替代质量证明。
涉及真实模型、推送、部署或旧资料改动时，继续遵循当次明确授权；不续用历史 halted 余额。
