# 0042 行为合同

1. 七个导航保留确认布局；新的wiki-workspace入口不导入wiki-preview-data、不恢复旧演示localStorage。加载/错误/空态、写入忙碌和迟到请求隔离必须真实。
2. 知识页列表/详情/版本与逐章节来源接0055；创建/更新进入显式选资料编译提案，extractive或model需清楚选择；负责人最后明确取消费用确认，model点击生成按钮直接提交一次，索引同样直接提交，busy防重复、不自动重试。accept/dismiss均以服务器回读为准，不假撤销终态。
3. 新后端0056提供持久未核验草稿与文件级原文查找。草稿不入索引、不自动发布，可保存问答文本但不宣称已核验知识。资料导入真实上传，parsed和indexed区分，显式索引及刷新任务；不自动重试写入或模型调用。
4. 知识页全文与类型过滤基于完整分页取回的页集合；资料全文查找由后端按文件归并后分页，不把TopK片段当文件总数。未完成完整加载时不能显示“全库”。
5. 原始资料有独立URL；Wiki引用保留page/proposal、version、sourceId上下文；答案引用保留answerId与citation。原文/图片/音视频读取真实服务器locator与同版本字节。离页释放媒体资源；PDF复用现有预览能力。
6. 问答直接调用现有knowledge-answers，无固定示例fallback。不伪造意图或逐阶段trace，只显示请求真实状态和引用。浏览器保留的会话明确本机缓存，不冒充跨设备持久会话；保存知识草稿为真实服务器写入。
7. 关系由完整知识页集合的共同document/publication/revision来源派生，明确“共同来源关系”，无猜测语义边；节点/列表/反链可导航。来源变化页显示stale并可重新编译新提案。
8. 检索设置保存真实v1/retrieval-settings（CAS、TopK1–20、有限实数阈值、权重）。模型配置在新版独立`#/models`页呈现，所有模型入口内部导航；复用ModelConfigurationSession/ModelRebuildSession及现有API，不另造模型协议。三角色保存、分别测试、应用、必要重建资格/任务/结果均使用服务器状态，不能只换链接标题。
9. 同源服务器复用现有身份与精确URL白名单，首轮开发18090→新Java18091；保留生产免登录决定但不部署。首轮启动终端、交付记录明确“本机合成资料/模型替身”，不称真实模型质量通过。下述新真实服务商批次必须另记实际模型与 Milvus，不能沿用替身标签或验收结果。
10. 负责人追加要求去掉杂乱备注：常驻页面只保留内容、标题、必要业务状态与操作；移除环境横幅、英文眉题、模型/提示版本串、开发说明及重复脚注。参数说明默认折叠；最后明确取消费用弹窗与上传费用小字，删除草稿确认保留。服务器追溯字段与校验不因显示精简而删除。
11. 模型页密钥仅write-only密码控件与一次请求输入；不放业务state/localStorage/URL，保存或离页清空，空值按既有合同保留同服务商旧密钥。输入只更新dirty/按钮状态，不能整页重绘打断编辑。busy防重复，unknown明确GET核对不自动重发。应用/重建成功须确认活动版本并刷新能力，清理旧答案状态；后台重建只有读取轮询，无虚假取消。只展示后端已开放三文字角色与向量库只读状态，不伪造ASR/VLM/BaseURL配置。
12. 最新授权允许本轮真实模型正常链：本机生产 JAR + 新隔离 data，使用线上相同 DeepSeek / 硅基流动角色与真实 Milvus 新 collection；模型全部实转发，所有服务商请求记入统一新 ledger，不复用旧余额，不自动重试失败。单资料导入索引、模型编译审阅采纳、综合问答与引用回读使用实际响应，不以固定替身答案补齐。首条闭环最多 6 次模型 HTTP 是执行自限，不是用户批准的数字额度；本轮不额外触发索引重建，不改生产或旧资料。结果以 root 实际记录为准。
13. 负责人随后明确分工：知识问答由其他智能体负责，本任务不再修改问答代码或追加提问，只推进资料入库、模型编译、审阅、版本与来源。范围切换前已发出的问答只读收尾，不代表接管问答；已有合同与历史证据保留。第 6 次实际用于知识页更新编译，其后的历史版本 / 原文与同库重启回读均为零模型请求。
